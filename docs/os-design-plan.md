# Unix-like 操作系统开发计划

## 目标
从头开发一个可在 QEMU 上运行的 Unix-like 操作系统，支持 x86_64 架构。

## 快速验证策略

### 单元测试 (Unit Test)
- 在宿主机上运行的纯逻辑测试
- 数据结构、算法、解析器等
- 使用标准测试框架 (如 cmocka)

### 集成测试 (Integration Test)
- 在 QEMU 中运行
- 内核启动后自动运行测试套件
- 通过串口输出测试结果

### 里程碑验证脚本
```bash
# 示例验证脚本
#!/bin/bash
qemu-system-x86_64 \
    -kernel kernel.bin \
    -serial stdio \
    -nographic \
    -no-reboot \
    | timeout 30 grep -q "TEST PASSED"
```

### 持续集成检查点
| 里程碑 | 触发条件 | 预期输出 |
|--------|----------|----------|
| M0 | 构建通过 | 生成 kernel.bin |
| M1 | Boot 完成 | 串口输出 "Kernel Started" |
| M2 | 内存就绪 | 串口输出 "Memory OK: XXX MB" |
| M3 | 中断就绪 | 响应定时器中断 |
| M4 | 调度就绪 | 多任务切换日志 |
| M5 | 系统调用就绪 | 用户程序输出 "Hello" |
| M6 | Shell 就绪 | Shell 提示符出现 |

## 技术选型建议

| 组件 | 推荐选择 | 理由 |
|------|----------|------|
| 语言 | C + 少量汇编 | 成熟、资料多 |
| 构建 | Makefile + Kconfig | 灵活、可配置 |
| 引导 | GRUB2 (Multiboot2) | 简化早期开发 |
| 调试 | QEMU + GDB | 支持单步调试 |
| 文件系统 | 先 ramfs，后 ext2 | 渐进式开发 |
| 网络 | virtio-net | QEMU 支持好 |

## 开发顺序建议 (无时间估计)

按优先级排序的开发顺序：

1. **必须首先完成**: F-* → B-* → D-01/D-02
2. **核心功能**: M-* → I-* → P-01~P-03
3. **用户态基础**: S-01~S-07 → U-01~U-03
4. **文件系统**: FS-01 → FS-10 → FS-02~FS-04
5. **完整用户体验**: U-04 → U-05 → IPC-*
6. **网络** (可选): N-*
7. **高级特性** (可选): A-*

## 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 调试困难 | 优先实现串口输出，使用 QEMU 日志 |
| 内存 bug | 使用 QEMU 地址 sanitizer |
| 进度阻塞 | 模块化设计，使用 mock/stub 解耦 |
| 并发 bug | 单核优先开发，后加 SMP |
